## Summary
The codebase has a clean, well-documented component/hook/lib layering with consistent naming conventions (PascalCase components, camelCase hooks/libs), but it carries real architectural debt: a stale, unused `contract.ts` that conflicts with the real `types.ts` shapes, two hooks (`useUnlock`, `useAppMeta`) whose logic was re-duplicated inline in pages instead of being reused, a haptic-feedback wrapper copy-pasted into eight+ files, and leftover debug code shipped in components. No circular dependencies were found among the shown files.

## Issues

No file in the codebase imports from '@/lib/contract'. It's dead, and worse, actively misleading since its docstring claims screens should 'assume' these signatures. — Files: src/lib/contract.ts, src/lib/types.ts / Fix: Delete contract.ts if it's obsolete scaffolding, or if it must stay as an interface spec, clearly mark it non-authoritative and reconcile its type names/shapes with types.ts so they can't silently diverge.

- [duplication] The 'try{ generateHapticFeedback(...) }catch{}' wrapper is copy-pasted with near-identical bodies (fireHaptic/fireTickWeak/fireSuccessHaftic) in at least 8 files instead of a single shared utility. — Files: src/components/BottomCTA.tsx, src/components/FloatingTabBar.tsx, src/components/ScoreSelector.tsx, src/components/SaveImageButton.tsx, src/pages/Home.tsx, src/pages/Offers.tsx, src/pages/Rank.tsx, src/pages/Weights.tsx / Fix: Extract a single `fireHaptic(type)` helper into e.g. src/lib/haptics.ts and import it everywhere instead of redefining the try/catch guard per file.
